# 公众号文章监测助手

> Chrome 扩展 · 自动监测多个公众号近期文章 · 批量导出为 Markdown

一个纯前端 Chrome 扩展（MV3），不依赖任何后端服务，**完全在浏览器本地**完成公众号文章抓取、分类与下载。

## 功能特性

### 监测与抓取
- **批量监测公众号**：一次添加 200+ 公众号，自动逐个拉取最近文章
- **并行加速**：3 个并发工作线程，267 个账号约 9 分钟
- **分页拉取**：每个公众号最多 5 页（50 篇），早于截止时间的自动停止
- **频率限制保护**：
  - 搜索接口最小间隔 **600ms**（实测安全阈值，0.5s 会被 200013 限流）
  - 200013/200003 触发时自动 30~60s 冷却后重试，最多重试 2 次
  - 文章接口失败有完整重试 + 日志记录

### 分类与组织
- **自定义分类**：左侧栏创建任意数量的分类（如"AI / 财经 / 科技"）
- **拖入即归类**：把公众号拖到对应分类下，或在右键菜单里选
- **未分类默认组**：未归类的账号统一进 `__uncategorized__`
- **持久化存储**：所有账号 / 分类 / Cookie 保存在 `chrome.storage.local`

### 文章查看与下载
- **左分类 + 右文章**两栏布局，响应式（≤768px 自动堆叠）
- **单篇下载**：点击按钮通过 `chrome.tabs.update` 打开文章页 → content script 抓取正文 → 转为 Markdown → 自动下载
- **批量下载**：勾选多篇，一次性导出为多个 `.md` 文件（ZIP 由浏览器原生处理）
- **批量导出 Markdown**：把当前分类下所有可见文章打包成 Markdown
- **DOM → Markdown 转换**：保留标题、列表、引用、代码块、表格、图片、链接等结构

### 日志系统（v3.0 新增）
- **全流程事件流**：START / OK / FAIL / COOL / RETRY / ART / ART-RL / ART-FAIL 等事件
- **相对时间戳**：从运行开始起算的 `+00:12.345` 格式
- **复制 / 下载 / 清空**：日志面板可一键复制到剪贴板、下载为 `.txt`、清空
- **容量 2000 行**：超出后自动截掉最旧事件

### 抗限流设计
- 全局搜索请求队列（Promise 链），无论几个 worker 都按 600ms 串行
- Token 失效（200001）自动停止并提示
- 单账号失败不影响其他账号继续
- 所有异常归类为「频率限制 / Token 无效 / 搜索失败 / 文章拉取失败」四类

## 安装

### 开发者模式加载

1. 打开 Chrome，访问 `chrome://extensions/`
2. 打开右上角 **「开发者模式」** 开关
3. 点击 **「加载已解压的扩展程序」**
4. 选择 `wechat-article-detection/` 目录
5. 安装完成后，扩展图标会出现在工具栏

> **注意**：Chrome MV3 不允许 `popup` 窗口用窗口大尺寸，所以本扩展把主界面以**全屏标签页**形式打开（通过 `background.js` 监听 `chrome.action.onClicked`）。

### 打包发布（可选）

```bash
# 在 wechat-article-detection/ 同级目录
zip -r wechat-article-detection-v3.0.zip wechat-article-detection/ \
  -x "*.DS_Store" "*/node_modules/*"
```

## 初次配置

### 1. 登录微信公众平台

打开 https://mp.weixin.qq.com/ 并扫码登录。**必须先登录**，扩展才能拿到所需的 `appmsg_token`、`cookie`、`passport` 等凭证。

### 2. 打开主界面

点击 Chrome 工具栏的扩展图标，会**自动打开一个全屏标签页**进入监测助手。

### 3. 验证凭证

扩展首次启动时自动从 `chrome.cookies` 读取以下域名下的 cookie：

- `*.weixin.qq.com`
- `*.qq.com`

并在状态栏显示「已加载 N 个凭证」。如果 N 为 0 或提示「凭证缺失」，请重新扫码登录。

## 使用方法

### 添加公众号

1. 左下角 **「+ 添加账号」** → 输入公众号名称 → 回车
2. **批量添加**：在弹出框中一次性粘贴多个账号，每行一个（`\n` 分隔）
   - 按 `Ctrl + Enter` 快速提交
3. 添加后账号默认进入 `未分类`

### 创建分类

1. 左下角 **「+ 新建分类」** → 输入分类名 → 回车
2. 拖动账号到分类，或右键账号 → **「移动到 → 分类名」**

### 开始监测

1. 顶部按钮 **「开始监测」**
2. 进度条 + 状态栏显示：
   - 当前正在处理的账号
   - 已完成数 / 总数
   - 触发限流时的倒计时（多个并行冷却可能互相覆盖，倒计时为参考）
3. 中途可点 **「停止」** 中断（已抓取的文章会保留）

### 下载文章

- **单篇**：文章卡片右下角 **「下载」** → 浏览器自动下载 `.md` 文件
- **批量**：
  1. 勾选多条（顶部「全选 / 取消全选」）
  2. 点 **「下载选中」** → 浏览器依次下载

### 导出 Markdown

顶部 **「导出 Markdown」** → 当前分类下所有文章以「`账号_标题.md`」命名批量下载。

### 查看日志

1. 顶部右侧 **「📋 日志」** 按钮 → 弹出日志面板
2. 按钮说明：
   - **复制日志**：复制到剪贴板
   - **下载日志**：保存为 `wechat-monitor-log-YYYYMMDD-HHMMSS.txt`
   - **清空日志**：清空当前面板（不会清空已下载的文件）

## 核心机制

### 抓取流程

```
点击「开始监测」
    ↓
runMonitor() ── 并发 3 个 worker
    ↓
processOne(account) ── 串行：search → articles
    ↓
searchFakeid(name) ── 进入全局搜索队列
    ↓
searchWithRetry(name) ── 3 次尝试，200013 触发 60s 冷却重试
    ↓
trySearchOnce(name) ── 实际请求 /cgi-bin/searchbiz
    ↓
fetchArticlesPageWithRetry(fakeid, page, name)
    ↓
monitorAccount(name) ── 分页拉取（每页 200ms 间隔，最多 5 页）
    ↓
content.js (article tab) ── DOM → Markdown → blobDownload
```

### 限流策略

| 接口 | 限流码 | 策略 |
|------|--------|------|
| 搜索 `/cgi-bin/searchbiz` | 200003 / 200013 | 队列强制 600ms 间隔 + 200013 自动 60s 冷却 × 2 次 |
| 文章 `/cgi-bin/appmsgpublish` | 200003 / 200013 | 30s 冷却 × 2 次重试 + 日志 |
| Token 失效 | 200001 | 立即停止并提示重新登录 |

### 搜索队列

```js
// popup.js:12-13
let _searchQueueTail = Promise.resolve();
const SEARCH_MIN_GAP_MS = 600;
```

每个搜索请求 `await _searchQueueTail` 后再 `setTimeout(600)` 触发下一个，保证 100 req/min 限速内。

### 并发模型

- **worker pool = 3**：`Promise.race` + `splice` 风格的轻量级池
- **搜索串行**：3 个 worker 共用同一全局队列，所以实际搜索速率 ≈ 1.5 个/秒
- **文章并行**：同一 worker 内的分页串行（200ms 间隔），不同 worker 完全并行

### DOM → Markdown

`content.js` 注入到文章页后：

1. `waitForContent(8000)` 等待 `#js_content` 加载
2. `extractTitle / extractAuthor / extractDate` 提取元数据
3. `domToMarkdown` 递归遍历（深度上限 30，防爆栈）
4. 处理：标题、段落、列表（有序/无序）、引用、代码块、表格、图片、链接、加粗、斜体、删除线
5. 跳过：`script / style / svg / iframe / display:none`

## 日志格式

每行一个事件，**第二列起为从运行开始的相对时间**：

```
00:00.000  RUN       267 个账号待监测
00:00.123  START     创见AI实验室
00:01.456  ART       创见AI实验室  n=12  pages=2
00:01.789  OK        创见AI实验室
00:02.012  START     极客公园
00:03.345  COOL      60s
00:03.345  RETRY     极客公园
00:04.567  ART-RL    极客公园  page=1  ret=200013  → 30s 冷却后重试 (第 1/2 次)
00:34.890  ART       极客公园  page=1  重试中…
00:35.123  ART       极客公园  n=8  pages=1
00:35.456  OK        极客公园
...
05:41.234  DONE      267  触发限流 13 次
```

| 事件 | 含义 |
|------|------|
| `RUN` | 本轮开始 |
| `START` | 开始处理某账号 |
| `ART` | 某账号文章拉取阶段（正常 / 重试中 / 完成） |
| `OK` | 某账号处理完成且有数据 |
| `FAIL` | 某账号处理失败（含 ret 码） |
| `COOL` | 触发限流，开始/结束冷却 |
| `RETRY` | 某账号被重试 |
| `ART-RL` | 文章接口 200013/200003 |
| `ART-FAIL` | 文章接口非限流错误 |
| `DONE` | 本轮全部完成，统计汇总 |

## 常见问题

### Q: 点击图标后没反应？
A: 检查 `chrome://extensions/` 里扩展是否启用，「收集错误」是否被关。

### Q: 提示「Token 无效 / 200001」？
A: 微信公众平台的 cookie 已过期，重新打开 https://mp.weixin.qq.com/ 扫码登录即可。

### Q: 大量 200013 / 200003 触发？
A: 调大 `popup.js:13` 的 `SEARCH_MIN_GAP_MS`（如 800 或 1000）。当前 600ms 适合 100 req/min 的稳态，超过这个速率会触发限流。

### Q: 同一篇文章拉两次？
A: 不会。`monitorAccount` 内的 `exhausted` 标志位在遇到早于截止时间的文章后立即停止后续分页。

### Q: 下载的 Markdown 没有图片？
A: `content.js` 已提取 `<img>` 标签，引用的是微信 CDN 原链接（防盗链可能 403）。如需本地化需自己加下载图片逻辑。

### Q: 内容脚本（content.js）被微信页面加密怎么办？
A: 当前版本对渲染后的 DOM 提取，对静态渲染的页面足够。如果微信改版为客户端渲染 / Shadow DOM，需要更新选择器。

### Q: 能监测付费 / 仅好友可见的文章吗？
A: 不能。只能抓取公众号对外公开的内容。

### Q: 扩展数据存哪里？
A: `chrome.storage.local`，不会上传任何服务器。清除扩展数据 = `chrome://extensions/` → 「移除」。
